# sageattention for RDNA4 (rdna4-sage)

rdna4-sage is an implementation of SageAttention 2.2 for AMD RDNA4 GPUs (RX 9070, RX 9070 XT, AI PRO R9700 and
the RX 9060 series). It accelerates the attention layers of diffusion transformer and video models such as Flux,
Qwen-Image, Wan and HunyuanVideo by computing them in 8-bit precision, with up to about 1.9x faster attention and
output that is visually indistinguishable from standard attention.

The package installs as a single wheel under the `sageattention` name and exposes the same API, so ComfyUI's
`--use-sage-attention` option and other SageAttention users work without modification. It supports Windows and
Linux and requires only a ROCm build of PyTorch; no Triton, compiler or ROCm SDK is needed at runtime. Calls that
the kernels do not support are handled by PyTorch's standard attention.

**Supported hardware:** RDNA4 GPUs only (gfx1200 / gfx1201). The kernels depend on RDNA4's 8-bit matrix
instructions. On other GPUs (RDNA3, RDNA2, Instinct, NVIDIA) all calls use PyTorch attention, and the original
SageAttention is the appropriate choice.

> **Wacky experiment.** This is a personal side project, not an AMD, FlyDSL or SageAttention release. The attention
> kernel is generated by patching a kernel from an unmerged draft FlyDSL PR
> ([#1223](https://github.com/ROCm/FlyDSL/pull/1223), gfx120x ops), and only gfx1201 has been tested on real hardware.
> The proper SageAttention kernel source for gfx120x should be added to FlyDSL itself once that PR is merged; this
> package is a stopgap until then. Use at your own risk; anything unsupported falls back to PyTorch SDPA.

## The short version

Attention is the slowest part of most modern image and video models: every token compares itself with every other
token, so a 1024² Flux image or a Wan video clip spends a big chunk of its time there. PyTorch's built-in attention
(SDPA) does that math in 16-bit. SageAttention's trick is to do the two big matrix multiplies in **8-bit** instead.
RDNA4 runs int8/fp8 matrix math at twice the fp16 rate, and the result stays close enough that you can't tell the
images apart.

This package is a SageAttention kernel written and tuned for RDNA4 specifically, so anything that calls `sageattn`
gets those 8-bit units without any other change.

### What's optimized

- **Q·Kᵀ in int8**, with one scale per query token and one per 32 key tokens.
- **P·V in fp8 (E4M3)**, with one scale per V channel, so loud channels don't crush quiet ones.
- **Hadamard rotation** of Q and K before quantizing. It spreads outlier values across the head dimension so int8
  loses less, and it cancels out exactly in Q·Kᵀ.
- **Kernel shaped for RDNA4's wave32 layout:** 32 query rows per wave, V transposed once in shared memory instead of
  shuffled on every step, and the running output only rescaled when the row max jumps a lot ("lazy rescale").
- **Quantization fused into two small kernels** (one for Q, one for K+V), so the 8-bit conversion doesn't eat the gain.
- **Causal and grouped-query attention** run natively in the kernel, so video models and GQA models (Lumina/Neta)
  don't fall back.
- **Smart routing:** short or small calls (text encoders, tiny resolutions, masked attention) go to SDPA, where
  8-bit would be slower or unsupported. The fast path is used only where it actually wins.

### What's different from standard SageAttention 2.2

| | SageAttention 2.2 | this package |
|---|---|---|
| Target GPUs | NVIDIA (CUDA kernels), plus community ROCm/Triton ports | AMD RDNA4 only (gfx1200 / gfx1201) |
| Outlier handling for K | "smooth K" (subtract K's mean) | Hadamard rotation of Q and K |
| P·V precision | fp8 or fp16, selectable | fp8 only |
| How kernels ship | compiled extension (or Triton JIT) tied to a GPU toolkit + torch + Python version | ahead-of-time code objects in one pure-Python wheel for any Python ≥ 3.10, Windows and Linux |
| Needs at runtime | CUDA, or Triton, depending on the build | just a ROCm build of torch |
| Wheel size | large (the Windows ROCm wheel carries ~2,000 kernels per GPU) | about 0.7 MB, 64 kernels |
| API | `sageattn`, `sageattn_varlen`, ... | the same functions and signatures; kernel-choice arguments are accepted and ignored |

### Benefits

- **Faster attention:** about 1.2x on SDXL, 1.3x on Flux and SD3.5, 1.6x on Flux.2 and Qwen-Image, and 1.7–1.9x on
  Wan and HunyuanVideo (per attention call, see [Performance](#performance)). Long video sequences gain the most.
- **Same-looking images:** cosine similarity ≈ 0.999 vs full-precision attention; side-by-side ComfyUI renders
  look the same.
- **Zero setup:** no Triton, compiler or ROCm SDK. Install one small wheel and `--use-sage-attention` works.
- **Works with `torch.compile`:** the kernel is a registered `torch.library` op, so `fullgraph=True` compiles cleanly.
- **Safe fallback:** anything it can't speed up runs normal PyTorch attention instead of erroring.

### What to expect

The speedup only matters as much as attention matters to the model. Big DiT and video models (Flux.2, Qwen-Image,
Wan, Hunyuan) see real end-to-end gains. Anima at 1024² goes from about 12.7 s to 11.9 s for 30 steps, and SDXL is a
tie because its time goes to convolutions. SD1.5's head sizes (40/80/160) aren't covered and just run SDPA. And like
any SageAttention it is lossy: small pixel differences against SDPA are expected.

## Drop-in SageAttention replacement

The wheel uses SageAttention's distribution name (`sageattention`) and import name, so it replaces an existing
SageAttention install and anything that does `from sageattention import sageattn` uses it without changes.

Requirements: a ROCm build of torch ≥ 2.10 (TheRock / AMD wheels on Windows, ROCm wheels on Linux) and an RX 9070 /
9060 series GPU. No Triton, FlyDSL, compiler or ROCm SDK is needed.

### 1. Build the wheel

The compiled kernels are checked in (`src/rdna4_sage/kernels/`), so building the wheel is plain Python packaging and
works on Windows or Linux. Only regenerating the kernels needs the FlyDSL toolchain (see [Build the kernels](#build-the-kernels)).

```
cd rdna4-sage
python -m pip wheel . -w dist --no-deps
```

This writes `dist/sageattention-2.2.0+rdna4.0.2.1-py3-none-any.whl` (pure Python + code objects, one wheel for every
Python version and both OSes). Skip this step if you already have the wheel.

### 2. Install it into the Python that runs ComfyUI

```
python -m pip uninstall -y sageattention
python -m pip install --no-deps dist/sageattention-2.2.0+rdna4.0.2.1-py3-none-any.whl
```

Use ComfyUI's venv python (`venv\Scripts\python.exe` on Windows, `python_embeded\python.exe` for the portable build).
`--no-deps` keeps pip from touching your ROCm torch.

### 3. Check it

```
python -c "import sageattention, rdna4_sage; print(sageattention.__version__, rdna4_sage.is_available())"
```

should print `2.2.0+rdna4.0.2.1 True`. `False` means the GPU is not gfx1200/gfx1201 or torch is not a ROCm build;
every call then runs torch SDPA.

### 4. Use it

- ComfyUI: start with `--use-sage-attention`, as with the original SageAttention.
- Custom nodes and wrappers that import `sageattention` (KJNodes' sage patch, video wrappers, ...) pick it up as is.
- Your own code: `from sageattention import sageattn` (see [Use](#use)).

To go back, `pip uninstall sageattention` and install the original SageAttention wheel.

### Contents

The wheel contains two packages:

- `sageattention`: the SageAttention 2.2 API (`sageattn`, `sageattn_varlen`, `sageattn_qk_int8_pv_fp16_triton`,
  `sageattn_qk_int8_pv_fp16_cuda`, `sageattn_qk_int8_pv_fp8_cuda`, `sageattn_qk_int8_pv_fp8_cuda_sm90`,
  `sageattn_qk_int8_pv_gfx12_native`) with SageAttention's signatures. Kernel-selection arguments (`qk_quant_gran`,
  `pv_accum_dtype`, `smooth_k`, `smooth_v`, `value_dtype`, ...) are accepted and ignored; `return_lse` returns the row
  logsumexp computed with torch (correct, slower).
- `rdna4_sage`: the kernels, the `torch.library` op and the ComfyUI backend.

## Use

```python
from sageattention import sageattn                        # ComfyUI --use-sage-attention, KJNodes, wrappers ...
out = sageattn(q, k, v, tensor_layout="HND", is_causal=False)

import rdna4_sage

out = rdna4_sage.sageattn(q, k, v, tensor_layout="HND")   # drop-in for sageattention.sageattn
out = rdna4_sage.attention(q, k, v, "NHD")                # kernel only; raises rdna4_sage.Unsupported otherwise
torch.ops.rdna4_sage.attention                            # torch.library op, works under torch.compile(fullgraph=True)
```

`sageattn` takes `(B, H, L, D)` ("HND") or `(B, L, H, D)` ("NHD") fp16/bf16 tensors with head dim 64, 96, 128 or 256
and returns the same layout and dtype. `is_causal=True` is supported (bottom-right aligned, as in SageAttention and
FlashAttention); the kernel handles causal self-attention (q_len == kv_len). It runs torch SDPA instead when the
kernel does not apply or would be slower:

- masks, `return_lse`, causal attention with q_len != kv_len
- other head dims (e.g. SD1.5's 40/80/160)
- GPUs other than gfx1200 / gfx1201
- small problems: kv length < `RDNA4_SAGE_MIN_KV` (1024) or batch·heads·q_len·kv_len < `RDNA4_SAGE_MIN_WORK` (64 Mi)

Grouped-query attention (query heads a multiple of kv heads) runs natively.

### ComfyUI

```python
import rdna4_sage.comfy
rdna4_sage.comfy.register()   # adds the "rdna4_sage" attention backend
```

Select it per model with `transformer_options["optimized_attention_override"]` or `preferred_attention`, the same way
as comfy's built-in backends. Masked calls fall back to comfy's pytorch attention.

## Performance

RX 9070 XT, Windows, torch 2.14 + ROCm 10.1, per attention call including quantization (`tests/bench_models.py`):

| model shape | SDPA | rdna4_sage | speedup |
|---|---|---|---|
| SDXL 1024, 4096-token level, batch 2 | 1.09 ms | 0.92 ms | 1.18x |
| SD3.5 Large joint, batch 2 | 4.01 ms | 2.98 ms | 1.34x |
| Flux.1 1024 | 2.51 ms | 1.97 ms | 1.27x |
| Flux.2 1024 | 6.43 ms | 4.04 ms | 1.59x |
| Qwen-Image 1328 | 7.11 ms | 4.46 ms | 1.59x |
| Neta Lumina 1024 (head dim 96) | 1.78 ms | 1.47 ms | 1.21x |
| Wan 2.1 1.3B 480p | 71.4 ms | 43.1 ms | 1.66x |
| Wan 2.1 14B 480p | 272 ms | 158 ms | 1.72x |
| HunyuanVideo 544p | 722 ms | 387 ms | 1.86x |
| AuraFlow 1024 (head dim 256), batch 2 | 5.48 ms | 4.75 ms | 1.15x |
| causal, 32 heads x 128, 16k tokens | 30.3 ms | 15.8 ms | 1.92x |

Accuracy against fp32 attention: cosine similarity ≈ 0.9992 on random inputs, 0.9993–0.9995 on outlier-heavy inputs.

## Build the kernels

Linux/WSL only. Needs ROCm 10.1, ROCm torch + Triton and a source build of FlyDSL PR #1223 (with its LLVM/MLIR);
the exact versions, setup steps and pinned `kernel_build/requirements.txt` are in
[`kernel_build/README.md`](kernel_build/README.md).

```
bash kernel_build/build.sh          # regenerates src/rdna4_sage/kernels for gfx1200 and gfx1201
python -m pip wheel . -w dist --no-deps --no-build-isolation
```
