# Building the rdna4-sage kernels

> **This is a wacky experiment.** The attention kernel here is produced by text transforms (`make_sage*.py`) applied
> to a kernel from an *unmerged draft* FlyDSL pull request, then compiled ahead of time and shipped as code objects.
> It works and is tested on an RX 9070 XT, but it is not how this should live long term. The proper home for an
> int8/fp8 SageAttention kernel for gfx120x is FlyDSL itself (`kernels/attention/` next to the other gfx120x
> kernels), written as real source rather than generated by string patches, once
> [FlyDSL PR #1223](https://github.com/ROCm/FlyDSL/pull/1223) or its successor is merged. At that point this
> directory should shrink to "compile these FlyDSL kernels ahead of time", or disappear in favour of FlyDSL / AOTriton
> shipping the kernels directly.

Everything here is only needed to **rebuild** `src/rdna4_sage/kernels/`. Using the wheel needs none of it.

## What the build does

1. `make_sage.py` → `make_sage_r2.py` → `make_sage_pkg.py` rewrite FlyDSL PR #1223's gfx120x FP8 flash attention
   kernel (`kernels/attention/flash_attn_fp8_gfx120x.py`) into `kernels/attention/flash_attn_sage_gfx120x.py` inside
   the FlyDSL checkout:
   int8 Q·Kᵀ with per-token Q / per-32-token K scales, fp8 P·V with per-channel V scales, V transposed in LDS,
   lazy O rescale, 32 query rows per wave (16 for head dim 256), causal masking, runtime head counts, bf16/fp16 output.
2. `compile_attn.py` compiles one attention variant per process with FlyDSL in compile-only mode for a target arch
   (`FLYDSL_GPU_ARCH`, `COMPILE_ONLY=1`), dumping the IR; `extract_hsaco.py` pulls the code object out of the dump.
3. `sage_quant.py` holds the Triton quantize kernels (Hadamard rotation, int8 Q/K, fp8 V); `build_kernels.py`
   compiles them with `triton.compile(..., target=GPUTarget("hip", arch, 32))`.
4. `build_kernels.py` builds every variant for gfx1200 and gfx1201, checks each code object's kernel-argument size
   against the layout the runtime packs, and writes `src/rdna4_sage/kernels/manifest.json`. The build is deterministic.

## Environment (as used for the shipped kernels)

| component | version |
|---|---|
| OS | Ubuntu 26.04.1 LTS under WSL on Windows 11, x86_64 |
| ROCm | 10.1 system install at `/opt/rocm` (only `/opt/rocm/llvm/bin/llvm-readelf` is used) |
| Python | 3.14.4 (+ `python3.14-dev` headers for the MLIR Python bindings) |
| Python packages | `requirements.txt` in this directory (torch 2.14.0+rocm10.1.0, Triton 3.8.0 ROCm, build tooling) |
| FlyDSL | source build of PR #1223: `https://github.com/dimitri91209/FlyDSL`, commit `59219efcc3c9a780bf080af811048f95081bc8f3` (reports `0.4.0.dev949`) |
| LLVM / MLIR | `e2a39f504fee836e4def9581bed817ecc327b9dc` (FlyDSL's `thirdparty/llvm-build-info.json`), `amd-minimal` profile |

A GPU is not required in principle (FlyDSL runs in compile-only mode and Triton cross-compiles), but the shipped
kernels were built with an RX 9070 XT present; a GPU-less build is untested.

## Setup (once, about 45 minutes, mostly LLVM)

```bash
# system packages
sudo apt install python3.14-venv python3.14-dev git build-essential

# build venv with ROCm torch, Triton and the build tooling
python3.14 -m venv ~/flypr && source ~/flypr/bin/activate
pip install -r requirements.txt

# FlyDSL source at the PR commit the transforms expect
git clone https://github.com/dimitri91209/FlyDSL ~/flydsl-pr
cd ~/flydsl-pr && git checkout 59219efcc3c9a780bf080af811048f95081bc8f3

# LLVM/MLIR (clones llvm-project next to the checkout, installs to ~/llvm-project/mlir_install)
LLVM_BUILD_PROFILE=amd-minimal bash scripts/build_llvm.sh -j$(nproc)

# FlyDSL itself, then an editable install into the venv
MLIR_PATH=~/llvm-project/mlir_install bash scripts/build.sh -j$(nproc)
pip install -e .
```

`build.sh` (below) expects exactly these locations: the venv at `~/flypr` and the checkout at `~/flydsl-pr`.

## Build

```bash
bash kernel_build/build.sh                    # all variants, gfx1200 + gfx1201
bash kernel_build/build.sh --archs gfx1201    # one arch, for quick iterations
python -m pip wheel . -w dist --no-deps --no-build-isolation   # then the wheel, from the project root
```

`build.sh` rewrites `kernels/attention/flash_attn_sage_gfx120x.py` in the FlyDSL checkout each run; the transforms
always start from the PR's original FP8 kernel, so no local FlyDSL commits are needed. `LLVM_READELF` overrides the
`/opt/rocm/llvm/bin/llvm-readelf` path.

## Adding or changing a variant

- Head dims and tile shapes: `ATTN_CONFIG` in `build_kernels.py` (`block_m`, row sub-tiles). The kernel builder
  asserts when the K loader would not tile a KV block (e.g. head dim 96 with 128 threads); always re-run
  `tests/test_attention.py` after a change, timings alone do not catch wrong output.
- The runtime reads everything it needs (kernel names, argument formats, thread counts, tile sizes) from
  `manifest.json`, so new head dims need no runtime code change beyond the supported-dims list it derives from it.
